# Data used by the repair agent, and where it came from

Every item here was generated by code in this repository. No outside text, code, model or dataset was used.

| Data | How it was made | Reproduce |
|---|---|---|
| Training traces (first 400 of 2,500) | `scripts/make-repair-data.mjs`, generator `scripts/drill-generators/repair.mjs`, seed 1. Failure messages and expected values come from running the code. | `node scripts/make-repair-data.mjs --count 2500 --seed 1 --out train.jsonl`; SHA-256 of the full file `701322f55b1581703812de852dba48d346cf6e2d43f8e5e07e4f749b9f6a3824` |
| Held-out traces (300) | same generator, seed 2 | `--count 300 --seed 2`; SHA-256 `cee93ec46678fc37f3bb066d1975b49cfae07bd77c3e99ba50961a6ca9bdaada` |
| Sealed set 1 (8 families, 16 defects) | written by hand for this project in `sealed-families.mjs`; expected values computed by running the correct version | in the file |
| Sealed set 2 (8 families, 15 defects) | written by hand for this project in `sealed-families-2.mjs`; same rule | in the file |

Generator behaviour is deterministic for a given seed, so the files can be regenerated and the hashes compared.

## What was not added, and why

No external text corpus was added for this work. The repair exam measures whether the model can fix code, and more
prose cannot change that: the character-level trainer already reproduces the repo's recorded next-character scores
(58.0% unseen, 63.5% seen) on the existing cited corpus (`training_data/open_corpus/CITATIONS.md`), and its repair
score stays at zero however much text it reads. The repo also asks for the smallest possible footprint
(`CLAUDE.md`, repository size). If you want more cited open text anyway, `scripts/fetch-open-corpus.mjs` adds it with
its manifest and licences. Say so and I will run it and report the size it adds.
